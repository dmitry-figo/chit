## Выбор платформы для быстрого старта
Изначально это Web (PWA).
Обоснование:
Распознавание речи из коробки. Web Speech API (SpeechRecognition) работает в Chrome, Edge, Safari (iOS 14.5+), на Android Chrome. Не нужно подключать сторонние ASR-сервисы, не нужны ключи, не нужна оплата.
Синтез речи тоже встроен (SpeechSynthesis) — приложение само озвучит правильный слог.
Один код — все устройства. Открыли на телефоне, планшете, ПК — работает. Не нужен Mac для сборки iOS, не нужен Android Studio для первой итерации.
PWA можно «установить» на домашний экран телефона — выглядит как приложение.
Потом легко масштабировать: оболочка через Capacitor/Cordova → публикация в Google Play и App Store без переписывания бизнес-логики. Либо переписать UI на Flutter/React Native, оставив ядро нетронутым.
Альтернативы и почему не они:
Flutter — хорошо для кроссплатформы, но плагины распознавания речи менее стабильны, чем нативный Web Speech API, и старт дольше.
React Native — требует настройки нативных модулей под речь, сложнее отладка.
Нативный Android/iOS — сразу запираем себя в одну платформу.
## Архитектура, которую закладываем сразу (чтобы потом не переделывать)
Разделяем на 4 независимых слоя:

│  UI (HTML/CSS/JS или позже React/Vue)   │  ← заменяем, не трогая остальное

Ключевой принцип: Domain и Data не знают, где запущены. Когда будем портировать под Android/iOS — заменим только UI и Speech-адаптер.
## Алгоритм обучения
Уровни слогов (от простого к сложному):
Прямые открытые: МА, МО, МУ, МЫ, МЭ
Обратные открытые: АМ, ОМ, УМ
С мягким знаком: МАМЬ, ЛЬДА
Со стечением согласных: ТРА, ВЗГ, СТРО
Йотированные: Я, Е, Ё, Ю, ЯМ, ЕЛ
Смешанные блоки из одного «гнезда» букв: МА-АМ-АМА-МАМА
Формирование блока (6–10 слогов):
Берём 3–4 «гнезда» букв текущего уровня.
Выводим все перестановки внутри гнезда (МА, АМ, АМА, МАА).
При повторном показе внутри блока — взвешенная случайность: слог с N ошибками выбирается с весом 1 + N·k (k ≈ 2). Так проблемные слоги будут всплывать чаще.
Правило завершения блока:
Для каждого слога считаем errors и correct.
Блок закрыт, когда для каждого слога выполнено correct ≥ max(2, 2·errors).
(Минимум 2 верных — чтобы даже безошибочные слоги закрепились, а не проскочили с одного раза.)
Награды:
Верный ответ: короткий приятный звук (колокольчик/«дзинь») + случайный смайлик из пула (😀🎉⭐👍🌟).
Конец блока: торжественный звук (фанфары ~2 сек) + крупный стикер (🏆🦄🚀🎊).
Ошибка: мягкий звук (не «бу!» — чтобы не демотивировать) + показ правильного слога через синтез речи.

## Важные нюансы для русского языка в Chrome:
Ё и Е. Браузер почти всегда заменяет Ё на Е. Если  в тренажере слоги с Ё (например, МЁД), нужно учитывать это при сравнении.
Мягкий знак и йотированные. Слоги типа ЛЬ, ЙА, Ю браузер часто искажает. Тут пригодится фонетическое сравнение (например, с помощью библиотеки metaphone или soundex, адаптированных под кириллицу, либо простых правил: ЙА == Я, ЛЬ == Л').

## Как именно ученик взаимодействует с блоком слогов?

UX «Карусель»: на экране один слог крупно. Прочитал верно → следующий.
Внизу — полоска прогресса (сколько слогов осталось до конца блока).
Минимум визуального шума, фокус на одном слоге, понятно «что сейчас делать». 

## План MVP (что делаем первым)
Экран 1: Старт → запрос разрешения микрофона → объяснение.
Экран 2: Показ блока слогов (крупно, по центру). Под ним — индикаторы прогресса по каждому слогу (сколько верных/ошибок).
Экран 3: Экран завершения блока — стикер + кнопка «Следующий блок».
Технически в MVP:
HTML + CSS + vanilla JS (без фреймворков — чтобы старт был максимально быстрым).

Сравнение: нормализация (toLowerCase, trim).
Хранение истории в localStorage (JSON: { "МА": {errors: 2, correct: 5}, ... }).
Звуки — короткие .mp3 (можно сгенерировать или взять свободные).
Вначале должно быть подробное логирование всех вариантов ASR для отладки.

Возраст/контекст: это для детей 5–7 лет, которые только учатся читать,  стиль мультяшный.
Озвучка: приятный мягкий голос девушки (молодой доброй тёти).
Статистика для родителя/учителя нужна (Отдельный экран с графиком прогресса)
Рабочий цикл: показали слог → слушали → сравнили → наградили/поправили.
Предусмотреть кнопки «не расслышал, повтори» и «пропустить».

## ⚠️ Важное про Web Speech API:
Web Speech API для русского языка работает в Chrome (десктоп и Android) и Safari (iOS 14.5+). Через file:// распознавание не запустится — нужен HTTP-сервер (python -m http.server 8000 или npx serve chit или в случае VS Code: расширение Live Server → правой кнопкой на index.html → Open with Live Server.)

### syllables.json — файл настроек тренировочных блоков слогов
Пояснения к структуре syllables.json:
*meta* — служебное, чтобы потом, когда файл будет редактироваться методистом, было понятно, что это и для кого.
*levels[].title и description* — используются на экране родителя (в статистике: «пройден уровень N: ...»).
*blocks[].letters* — «гнездо» букв. Можно показывать ребёнку подсказку «собирай из М и А» (опционально, в MVP не обязательно).
*blocks[].syllables* — именно это выводится на экран в рамках блока. Все слоги блока построены из одних и тех же букв — это и есть суть методики.
Порядок внутри блока — намеренно не алфавитный: сначала прямой слог (МА), потом обратный (АМ), потом удлинённые (АМА, МАА). Это соответствует логике «от простого к сложному».
